## Unreleased

## 1.3.0 — 2026-07-09

The bundled web UI is redesigned as the **Clarity console** — a fixed set of operational screens (Overview, Explore, Metrics, Logs, Alerts, Settings) with a first-class light/dark theme, alongside the existing user-built dashboards (now under **Manage**). This release also lands configurable ingest windows (ADR-0017) and the OTLP `0.32` proto bump. All 13 workspace crates at 1.3.0; the on-disk WAL and Parquet formats are unchanged.

### Added

- **Clarity console redesign** (bundled `pharlux-ui`). The web UI is rebuilt as a fixed-screen console served from the same embedded binary: **Overview** (at-a-glance KPIs, ingest throughput, log severity, recent logs, firing alerts), **Explore** (SQL over metrics & logs with a schema rail and Table/Chart/JSON results), **Metrics** (a live small-multiples explorer of the metric names actually flowing in), **Logs** (severity histogram, event stream, and a detail drawer whose trace context is built from log records sharing a `trace_id`), **Alerts** (rule status + create/delete), and a read-only **Settings** screen with a live theme control. One design system, two themes (dark default + light + system, remembered per device). The existing user-built dashboards are kept and restyled under **Manage**. Every screen reads live data through the documented query and admin APIs — no new server endpoints. See [Dashboards & the console](/docs/dashboards).
- **Dashboard global time range + auto-refresh** (bundled web UI, dashboard redesign Slices 5–6). Dashboards gain a header time-range picker (Last 15m / 1h / 2h / 24h, or a custom absolute window) and an auto-refresh interval (off / 10s / 30s / 1m / 5m). Panels reference the selected window through two reserved SQL tokens, `$__timeFrom` / `$__timeTo`, which resolve to safe SQL bounds (`now() - INTERVAL '…'` for presets, validated `TIMESTAMP '…'` literals for a custom window) — injection-safe by construction and substituted client-side, so the server still sees ordinary SQL. Both controls have a saved default in the layout JSON (optional top-level `timeRange` / `refresh` keys) that a viewer can override for their session without changing the saved dashboard; the keys round-trip through export/import. A panel that omits the tokens is not time-filtered. The change is entirely in the embedded `pharlux-ui`. Also adds responsive panel-grid stacking (tablet/mobile) and a `prefers-reduced-motion` pass.

### Fixed

- **Configured ingest windows are now honoured (ADR-0017).** The documented `[ingest].late_arrival_window_seconds` / `reject_future_seconds` settings were previously inert — timestamp validation hard-coded a ±1h bound. They are now threaded through the OTLP translate path (HTTP and gRPC) with an asymmetric accept window `(-reject_future .. +late_arrival)`. The default remains 1h/1h, so default runtime behaviour is unchanged. (#59)

### Security

- Bumped `opentelemetry-proto` `0.31.0` → `0.32.0`, which moves `opentelemetry` and `opentelemetry_sdk` to the `0.32` line and clears the outstanding RustSec advisory against `opentelemetry_sdk 0.31` (the vulnerable code path — the baggage propagator — is not reachable from Pharlux, but the bump removes the advisory at its source rather than suppressing it). The `prost` / `tonic` pins are unchanged; the only new transitive dependency is `portable-atomic`. OTLP 0.32 adds an experimental string-table (`strindex`) variant to `AnyValue` / `KeyValue`; the ingest translate path handles the new `AnyValue` variant best-effort without panicking on untrusted input. No behaviour change for conformant OTLP metrics/logs traffic.

## 1.2.0 — 2026-06-30

WAL group commit: the ingest writer now amortizes a single `fsync` across a whole group of queued records instead of one `fsync` per batch (ADR-0023). This removes the per-batch fsync bottleneck that capped sustained _durable_ ingest on slow-fsync disks. All 13 workspace crates at 1.2.0; no Rust / Cargo dependency changes. The on-disk WAL format is unchanged.

### Changed

- **WAL group commit (ADR-0023).** The ingest drain pulls up to 256 queued requests (`recv_many`), stages them into one buffer, and persists them with a single `write_all` + single `sync_data()` per group (`append_group`), instead of one `fsync` per batch. The on-disk record framing (length prefix + prost + CRC32 trailer, ADR-0018) is **unchanged** — a group is simply N framed records made durable together. The OTLP ack stays asynchronous (200 on channel-accept; durability follows within the next group fsync). The benefit is largest at small batch sizes, where per-batch fsync dominates; at large batches the per-batch cost is already amortized, so the gain narrows. Sustained-ingest throughput is reproducible with the `pharlux-loadtest` harness in the source tree. (#48)

### Internal

- **Group commit is all-or-nothing.** Every error path (allocation, encode, ceiling, write/fsync, boundary rotation) leaves the group neither durable nor seq-consuming. Rotation happens at the group boundary _before_ the next group is written, so a rotation failure can never strand an already-durable group behind an error. The staging buffer uses `try_reserve_exact`, surfacing an allocation failure as a recoverable error rather than aborting the process on the ingest hot path. (#48)

## 1.1.3 — 2026-06-26

Dashboard variables and a host filter for the bundled web UI (dashboard redesign Slice 4). Ships entirely in the embedded UI — no dependency changes.

### Added

- **Dashboard variables / host filter.** Dashboards may declare an optional top-level `variables` array; the bundled UI renders a header filter bar whose selection is substituted into every panel's SQL before it runs. Options come from a tenant-scoped query or a static list. A multi-select host filter is written `WHERE resource['host.name'] IN ($hosts)`; an empty selection substitutes `NULL`. Substitution is client-side and injection-safe by construction (values are allowlisted to the variable's option set and emitted as single-quote-escaped SQL string literals). Dashboards without a `variables` key are unchanged.

## 1.1.2 — 2026-06-26

Read-path memory fix completion: query scans now stream Parquet instead of materialising the full dataset, so peak memory tracks the query working set rather than total data on disk. No dependency changes.

### Changed

- Metrics and logs queries stream WAL + Parquet record batches through a bounded channel instead of building an in-memory table over every batch, bounding read-path memory regardless of whether a query carries a time predicate (prong-2 of the read-path OOM fix; complements the 1.1.1 partition pruning). Parquet file handles are still opened under the read lock, so a concurrent compaction/retention unlink cannot drop a file mid-scan.

### Fixed

- Parquet handle acquisition no longer silently drops a partition on an open failure: a benign compaction/retention unlink race is skipped, while any other error propagates with the failing path — so query results are never silently truncated.

## 1.1.1 — 2026-06-24

Read-path OOM fix plus dashboard redesign Wave 1.

### Added

- Dashboard redesign Wave 1: a design-token system, a shared ECharts theme, self-hosted IBM Plex fonts, new time-series and stat (single-value KPI with sparkline, delta, and ascending thresholds) panel types, and token-themed CodeMirror SQL/JSON editors.
- Read-only dashboard view mode.

### Fixed

- Read-path memory growth: under sustained fleet load, production RSS climbed toward OOM because the scanner materialised every Parquet file into a single in-memory table before filtering. Scans now prune Parquet partitions by time and tenant up front, bounding read-path memory to the query window instead of the whole dataset (prong-1; the streaming follow-up landed in 1.1.2).
- Stat and time-series panels no longer coerce `NULL` to `0` (which fabricated datapoints and false zero-drops) — a null now stays a real gap.
- Multi-series colour and legend order is stable (series sorted by name instead of row order).
- The login footer version is read live from the public health endpoint rather than a hardcoded string that drifted from the release.

### Changed

- Frontend dependencies: added IBM Plex Sans/Mono and CodeMirror language packages; removed the one-dark theme.

## 1.1.0 — 2026-06-21

The clean-install hardening release: bound the WAL and fail loud. Validated end-to-end on a fresh 4&nbsp;vCPU&nbsp;/&nbsp;8&nbsp;GB box — bounded WAL, plateaued RSS, zero restarts, and graceful backpressure where v1.0.0 OOM-looped.

### Added

- gzip / zstd decompression for OTLP ingest (collectors no longer need `compression: none`).
- Operator recovery runbook: a health ladder and a wedged-store recovery procedure.
- Per-tenant retention sweep, wired and clamped to the licensed retention cap.
- Licensed host-cap enforcement at the OTLP ingest boundary.
- `[license]` config section and the `pharlux license verify` CLI for the ValidonX licensing verifier, with a revoke webhook and license-provider wiring.
- CodeQL static-analysis workflow for Rust.
- `deny.toml` promoted to a blocking CI gate, plus Dependabot.
- `CODE_OF_CONDUCT.md` and `NOTICE` for go-public readiness.
- `.cargo/audit.toml` mirroring `deny.toml`'s advisory-ignore list so `cargo audit` and `cargo deny check` agree.

### Fixed

- Unbounded WAL stall: the WAL is now kept bounded under sustained load via reclaim / truncate-on-flush, instead of growing to the hard ceiling and silently rejecting every append while the service still reported `active`.
- Boot-time OOM: WAL replay now streams with chunked flush, bounding boot-time RSS instead of collecting the whole WAL into memory.
- Clean-shutdown handshake: truncate plus a sentinel marker so a clean restart skips WAL replay entirely.
- WAL append atomicity on a write/fsync error — the writer truncates and rolls back the sequence number rather than leaving orphan bytes that replay would silently skip.
- Durable checkpoint with a degraded-health signal after repeated checkpoint-write failures.
- Integer-math health thresholds (no floating-point drift in the health ladder).
- SPA fallback no longer shadows `/api/*`: unmatched API routes return a JSON 404 instead of the dashboard `index.html`.
- Alerting survives a poisoned store lock so the circuit breaker stays effective.

### Changed

- Server bootstrap extracted into `pharlux-server` with provider injection, separating the community binary shim from the server library.

### Security

- Bumped `tar` to 0.4.46 (GHSA-3pv8-6f4r-ffg2).
- Bumped frontend dependencies to clear Dependabot alerts.

## 1.0.0 — 2026-04-17

First public release. V1 feature-complete. All Phase 0, 1, 2, and 3 exit gates passed.

Version 1.0.0 signals a commitment to semver on the public API surface: the REST endpoints, the `pharlux.toml` config schema, the OTLP ingest subset, the Parquet on-disk schemas, and the WAL record framing. Breaking changes to any of these require a 2.0.0 bump.

### Added

#### Storage

- Production WAL (prost + CRC32 + length prefix) with segment rotation and tenant-aware replay
- Parquet writer with per-signal, per-tenant, hourly partitioning
- Per-tenant retention, manual compaction with crash-safe marker protocol
- WAL + Parquet union TableProvider for DataFusion (RwLock snapshot design)

#### Ingestion

- OTLP gRPC (port 4317): MetricsService + LogsService
- OTLP HTTP/protobuf (port 4318): `/v1/metrics` + `/v1/logs`
- Backpressure: bounded mpsc channel, HTTP 429 / gRPC RESOURCE_EXHAUSTED
- Timestamp validation, metric name validation, attribute length caps, 2 MB body limit
- TenantResolver trait for API-key-to-tenant mapping

#### Query

- DataFusion QueryEngine with logical-plan tenant filter on every TableScan
- Per-request SessionContext, 256 MB MemoryPool cap

#### Auth

- JWT (HS256) with required exp claim, Argon2id (OWASP 2023: 19 MiB)
- SQLite user/API key tables, tenant-scoped operations

#### API

- REST: `/health`, `/query`, `/auth/login`, `/metrics`, `/admin/tenants` (CRUD)
- Prometheus exposition at `GET /metrics` with live atomic counters

#### Alerting

- SQL-based rules in SQLite, state machine (OK/PENDING/FIRING/RESOLVED)
- Circuit breaker: 3 consecutive panics → self-disable (Decision 16)

#### Frontend

- React 18 + TypeScript + Vite, embedded via rust-embed
- Login, SQL editor (CodeMirror 6), Dashboard (ECharts: metrics bar, log severity pie, recent logs)

#### CLI

- Subcommands: `compact`, `backup`, `install`, `migrate`, `version`
- Single-binary deployment (Axum + Tonic on shared Tokio runtime)

#### Documentation

- Getting started, OTLP config reference, SQL query reference
- Logs query performance (10 GB/day LIKE threshold), reverse proxy (Caddy/nginx), backup/restore

### Performance

- 250k pts/sec sustained 30s, 0 errors, ~117&nbsp;ms avg latency (4&nbsp;vCPU&nbsp;/&nbsp;8&nbsp;GB)
- 81&nbsp;MB statically-linked musl binary

### Testing

- 149 tests, crash recovery 10/10, e2e integration test, cross-signal JOIN
- clippy clean, fmt clean

### Security

- Outbound HTTP TLS backend is `rustls` (no OpenSSL in the dep tree). Applies to webhook and Slack alert notifications and the load-test client. Enables a genuinely OpenSSL-free musl static-pie binary.
- Refuse to start when `jwt.secret` is world-readable (the "other read" bit is set). Documented in `SECURITY.md` under "Secret handling".
- Bumped `tar` from `0.4.44` to `0.4.45` for RUSTSEC-2026-0067 (`unpack_in` symlink chmod escape) and RUSTSEC-2026-0068 (PAX size-header inconsistency). Used by the `pharlux backup` subcommand.
- Bumped `rustls-webpki` (transitive via `rustls` → `reqwest`) to 0.103.13 for RUSTSEC-2026-0098 / -0099 (name-constraint bypasses) and RUSTSEC-2026-0104 (reachable panic in CRL parsing).
- Bumped `rand` to 0.9.4 / 0.8.6 for RUSTSEC-2026-0097 (unsoundness with a custom `log` logger). Not reachable in Pharlux's build (we use `tracing`), but the patch is taken on principle.
- Documented one remaining unfixable advisory with a reachability justification: RUSTSEC-2023-0071 (`rsa` Marvin attack). Pharlux uses `jsonwebtoken` with HS256 only, so the RSA decryption paths the attack targets are unreachable. No upstream fix exists; recorded in `deny.toml` with re-evaluation steps if RS256/384/512 is ever added.
- New `deny.toml` policy for `cargo deny check`: SPDX license allow-list, a hard no-OpenSSL TLS ban, the justified per-advisory ignore list, and crates.io as the only allowed registry.
